## 一、为什么用 Electron，以及它为什么不是"网页套壳"

先说清楚这件事，因为它直接决定你的观感。

Electron 的渲染层确实是 Chromium，但**决定一个程序"看起来老不老"的从来不是渲染引擎，而是设计系统**。大量 2015 年前后的桌面软件用的也是 Web 技术，难看是因为：灰底渐变按钮、3D 立体描边、11px 密集文字、表格每一格都画线、顶部一条「文件 / 编辑 / 查看」原生菜单栏。

这些全部可以逐条干掉，而 Electron 恰好给了你干掉它们的自由：

| 老程序的痕迹 | 本方案的做法 |
|---|---|
| 系统原生标题栏（Win10 白条 + Win11 大圆角混搭） | **无边框窗口**，自绘 44px 标题栏，与内容同一套配色，可整条拖动 |
| 顶部「文件 编辑 视图 帮助」菜单栏 | 没有菜单栏。功能靠侧栏 + `⌘K` 命令面板 |
| 灰底 + 3D 凸起按钮 | 纯平面，无渐变无投影，只用留白和 0.5px 发丝线分层 |
| 表格满格线框 | 只有水平发丝线，无竖线，行高 52px |
| 12px 挤在一起的文字 | 正文 13px、行高 1.6，标题 20px |
| 系统默认蓝色选中条 | 单一强调色，选中用极淡填充药丸，不用色条 |

顺带的好处：UI 用 React 写，你以后想改配色、调布局就是改几个 CSS 变量，不用碰 C# 或 Qt。

**代价（说实话）**：安装包约 110–130MB，内存占用约 200MB，冷启动 1–2 秒。如果这三个数字你都不能接受，唯一的替代是 Tauri（约 40MB），但后端要换成 Rust 或额外挂一个 Node sidecar，工期会多 3–4 天且稳定性风险更高。**我建议 Electron，除非你对体积有硬要求。**

### 1.1 进程模型

```
┌──────────────────────────────────────────────────────────────┐
│  库存管理.exe  (Electron)                                     │
│                                                              │
│  ┌────────────────────────┐   ┌───────────────────────────┐  │
│  │ 渲染进程 (React)        │   │ 主进程 (Node)              │  │
│  │ · 界面、表格、表单      │◄─►│ · IPC 路由                 │  │
│  │ · 无 Node 权限          │IPC│ · service / repository     │  │
│  │ · contextIsolation 开启 │   │ · MCP HTTP :8788          │  │
│  └────────────────────────┘   │ · 备份 / 对账定时任务       │  │
│                                └────────────┬──────────────┘  │
└─────────────────────────────────────────────┼─────────────────┘
                                              │
                        ┌─────────────────────▼─────────────────┐
                        │  %APPDATA%\InventoryManager\data\      │
                        │  inventory.db (SQLite · WAL)           │
                        │  files\  backups\  exports\            │
                        └─────────────────────▲─────────────────┘
                                              │ 仅通过 MCP HTTP 访问
                        ┌─────────────────────┴─────────────────┐
                        │  mcp-bridge.exe  (约 15MB)             │
                        │  stdio ⇄ http://127.0.0.1:8788 转发    │
                        │  供 WorkBuddy / Codex 等 spawn 型客户端 │
                        └───────────────────────────────────────┘
```

**为什么 UI 走 IPC 而不是本地 HTTP**：不占端口、不经 TCP 栈、延迟低一个数量级，也不用操心端口冲突和 CORS。渲染进程永远碰不到数据库和文件系统，只通过一份白名单 IPC 通道拿数据 —— 这比网页方案的攻击面更小。

**为什么 MCP 不走 IPC**：MCP 是给外部 AI 客户端用的，必须有一个进程外的入口。所以在主进程里起一个只监听 `127.0.0.1:8788` 的 MCP HTTP 服务，带 Bearer Token。WorkBuddy / 豆包工作版这类支持 HTTP 的直接连；Codex 这类只会 spawn 子进程的，用 `mcp-bridge.exe` 做 stdio→HTTP 转发（它是纯 JS 无原生依赖，用 Node SEA 打包成 15MB 单文件，启动几十毫秒）。

**代价**：主程序得在运行。所以设计成**关窗口不退出，最小化到系统托盘**，并支持开机自启。托盘图标右键可「快速入库」「打开主界面」「退出」。这样 AI 随时能加库存。

**单实例锁**：Electron `requestSingleInstanceLock()` 保证只有一个实例，第二次双击是唤醒已有窗口，避免两个进程同时写库。

## 二、数据模型

数据库：`%APPDATA%\InventoryManager\data\inventory.db`（WAL + `synchronous=NORMAL` + `foreign_keys=ON`）

### 2.1 suppliers（供应商）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | TEXT PK | nanoid(12) |
| code | TEXT UNIQUE | 编号，如 `SUP-001` |
| name | TEXT NOT NULL | 全称（唯一索引） |
| short_name | TEXT | 简称 |
| contact_name | TEXT | 联系人 |
| phone / email | TEXT | |
| address | TEXT | |
| website | TEXT | 官网 / 商城链接 |
| payment_terms | TEXT | 账期 |
| level | INTEGER | 评级 1-5 |
| tags | TEXT | 逗号分隔 |
| note | TEXT | |
| status | TEXT | `active` / `archived` |
| created_at / updated_at | TEXT | ISO-8601 |

### 2.2 storage_locations（存放位置）

「编码 + 可嵌套树」，支持 `A-02-03` 简洁编码，也支持「A柜 > 第2层 > 第3盒」的层级查询。

| 字段 | 说明 |
|---|---|
| id / parent_id | 自关联，最多 4 层 |
| code | 本层编码，如 `02` |
| full_code | 完整路径 `A-02-03`（唯一），列表直接展示 |
| name | 可读名，如 `A柜第2层第3盒` |
| kind | `room` / `rack` / `layer` / `box` |
| capacity / note | 容量提示 / 备注 |

### 2.3 components（电子元器件 / 芯片）

| 字段 | 说明 |
|---|---|
| id | 主键 |
| **part_number** | 型号，如 `STM32F103C8T6` |
| **manufacturer** | 厂商 |
| category | MCU / 电源管理 / 运放 / 存储 / 逻辑 / 连接器 / 被动件 / 传感器 / 模块 |
| package | 封装 `LQFP-48` / `0402` |
| description | 描述 |
| date_code | 批次号 |
| packaging | 盘装 / 管装 / 托盘 / 散装 |
| **quantity** | 当前库存 |
| unit | 单位 |
| **safety_stock** | 安全库存阈值 |
| unit_price / currency | 参考单价 |
| moq | 最小起订量 |
| msl | 湿敏等级 1-6（专业字段，折叠） |
| rohs | 0 / 1 |
| **location_id** + location_full_code | 存放位置（冗余编码，列表免 JOIN） |
| supplier_id | 主供应商 |
| image_path / tags / note | |
| status | `active` / `archived` |

唯一键 `UNIQUE(part_number, manufacturer)` —— MCP 批量 upsert 的幂等基础。

### 2.4 stock_movements（出入库流水）

`component_id / type(in|out|adjust|init) / quantity(出库为负) / before_qty / after_qty / unit_price / supplier_id / date_code / project_ref / operator / note / occurred_at / created_at`

`operator` 区分来源：`local`（界面操作）或 `mcp:workbuddy` / `mcp:codex` / `mcp:doubao`。界面上能筛出"AI 干了什么"。

**一致性**：`components.quantity` 是冗余值，所有变更必须在同一事务内「写流水 + 回写库存」，校验 `after_qty = before_qty + quantity` 且 `after_qty >= 0`。另有每日对账任务比对 `SUM(quantity)` 与实际库存。

### 2.5 其他表

- `attachments`：`component_id / kind(image|datasheet|other) / file_path / mime / size / sha256`，按内容哈希去重
- `settings`：端口、MCP Token、数据目录、主题、托盘行为
- `mcp_operation_log`：幂等键 + 结果快照（保留 24h）
- `import_batches`：导入批次，支持整批回滚
- `audit_log`：删除、批量修改、盘点

### 2.6 索引与搜索

筛选维度全部建 B-tree 索引：`part_number`、`manufacturer`、`category`、`location_full_code`、`supplier_id`、`status`、`(quantity, safety_stock)`。

关键词分两级：**≥3 字符** 走 FTS5 `tokenize='trigram'`（中文子串与型号都有效）；**1-2 字符** 走 `LIKE`，1 万行下约 5-10ms。搜索范围覆盖型号、厂商、描述、标签、位置编码、备注。

## 三、界面设计（重做）

这一版的设计目标是**简约的美**，不是"功能齐全的表格工具"。三条原则：

1. **一屏只留一个视觉重点**。主按钮只有一个，强调色只出现在需要你注意的地方。
2. **用留白分层，不用线框分层**。整页只有 0.5px 发丝线，且只画水平方向。
3. **不打扰**。没有弹窗打断、没有红黄绿三色标签墙、没有闪烁。

### 3.1 设计令牌

| 类别 | 浅色 | 深色 |
|---|---|---|
| 应用底色 | `#FAFAF9` 暖白 | `#0F0F0E` |
| 侧栏 | `#F5F5F3` | `#161615` |
| 内容面 / 卡片 | `#FFFFFF` | `#1A1A19` |
| 主文字 | `#1A1A19` | `#F2F2F0` |
| 次文字 | `#71716E` | `#9C9B97` |
| 弱文字（表头、提示） | `#A3A29E` | `#6E6D6A` |
| 发丝线 | `rgba(20,20,19,0.07)` | `rgba(255,255,255,0.08)` |
| **强调色** | `#4F46E5` 靛蓝 | `#818CF8` |
| 强调底（选中/悬停） | `rgba(79,70,229,0.07)` | `rgba(129,140,248,0.12)` |
| 预警 | `#B45309` 琥珀 | `#FBBF24` |
| 危险 | `#B91C1C` | `#F87171` |

**全应用只有 1 个强调色 + 2 个语义色**。这是"简约"最容易被破坏的地方——一旦出现第五种颜色，再好的排版也会显得杂。

**字体**：`"Inter var", "Segoe UI Variable Text", "Segoe UI", "Microsoft YaHei UI", system-ui`
**字号**：页面标题 20px/500 · 区块标题 14px/500 · 正文 13px/400 · 辅助 12px/400 · 表格数字 `tabular-nums`
**圆角**：卡片 12px · 控件 8px · 药丸 999px。全局只用这三档。
**间距**：8px 栅格。页面边距 28px，区块间距 20px，控件间距 8px。
**动效**：120–160ms `ease-out`，只做 `opacity` 和 `translateY(2px)`。不做弹跳、不做缩放。

### 3.2 窗口结构

```
┌────────────────────────────────────────────────────────────────┐
│  库存管理                                    ─   □   ×        │ ← 44px 自绘标题栏，可拖动
├──────────┬─────────────────────────────────────────────────────┤
│          │  电子元器件                          ＋ 新建         │ ← 页头 20px 标题
│ 概览      │  共 1 284 种物料 · 2 种低于安全库存                    │
│ 元器件 ◀  │                                                     │
│ 供应商    │  ┌───────────────────────┐  ⚙  ⇅  ⤓  ⤒          │ ← 工具条
│ 流水      │  │ 搜索型号、厂商、位置…   │  筛选  排序 导出 导入   │
│ 位置      │  └───────────────────────┘                         │
│ 设置      │                                                     │
│          │  型号              厂商    分类     库存    位置      │ ← 表头 12px 弱色
│          │  ─────────────────────────────────────────────────  │
│          │  STM32F103C8T6    ST     MCU      340   A-02-03   │ ← 行高 52
│          │  TPS5430DDA       TI     电源管理  ·18   C-03-01   │
│          │  …                                                 │
└──────────┴─────────────────────────────────────────────────────┘
```

- **标题栏**：无系统边框。左侧应用名 13px/500，右侧三个 32×32 圆角按钮，**悬停才出现浅色背景**，关闭按钮悬停才变红。整条可拖动，双击最大化。
- **侧栏**：208px，比内容区深半档。菜单项 36px 高、13px 字、8px 圆角。选中项是**极淡强调底 + 强调色文字**，没有左侧竖条、没有图标跳动。
- **页头**：标题 + 一行灰色统计说明，右侧一个主按钮。主按钮是唯一有实底色的元素。
- **表格**：无竖线、无斑马纹、无边框卡片包裹。只有行间 0.5px 发丝线，最后一行不画。悬停整行 `#FAFAF9`。数字右对齐。
- **低库存**：**不加背景色块、不加红标签**，只在数字前一个 4px 琥珀圆点 + 数字用琥珀色。克制到几乎看不见，但你扫一眼就知道。

### 3.3 关键交互

- **`⌘K` / `Ctrl+K` 命令面板**：搜物料、跳页面、执行"新建元器件"。一个输入框走遍全应用，这是现代桌面程序和数据录入工具最大的体验分水岭。
- `/` 聚焦搜索，`N` 新建，`Esc` 关抽屉，方向键在表格内移动，`Enter` 打开详情。
- **详情用右侧抽屉**（480px 宽，从右滑入 160ms），不跳页。关闭即回到原位置、原滚动位置。
- **行内快捷出入库**：行尾悬停出现「＋ −」两个小按钮，点开一个输入数量的浮层，回车完成。两次操作搞定，不用进详情。
- 搜索 200ms 防抖 + 请求取消，输入过程不闪回旧结果。
- 所有异步操作有骨架屏 / 按钮内联 loading / 右上角轻提示。**绝不出现"点了没反应"**。
- 首次启动的空状态：一句说明 + 一个「导入现有表格」主按钮 + 一个「手动新建」次按钮。不放插画，保持克制。

### 3.4 概览页

四张指标卡（SKU 数、总库存、预警数、本月出入库笔数）+ 近 30 天出入库趋势细线图 + 低库存 Top 10 + 位置占用分布。图表用极细线条、无网格、无图例框，颜色只用强调色和琥珀。

## 四、业务接口（IPC 通道）

渲染进程通过 `window.api.invoke(channel, payload)` 调用，通道用共享 Zod schema 约束入参与返回值，端到端类型安全。preload 用 `contextBridge` 白名单暴露，渲染进程 `nodeIntegration: false`、`contextIsolation: true`、`sandbox: true`。

| 通道 | 说明 |
|---|---|
| `components:list` | `q, manufacturer, category, locationCode, supplierId, lowStock, sort, page, pageSize` |
| `components:get` / `create` / `update` / `archive` | 详情 / 新建 / 更新 / 软归档 |
| `components:movements` | 该物料流水 |
| `suppliers:list` / `get` / `create` / `update` / `archive` | 供应商 CRUD |
| `suppliers:components` | 该供应商供货物料 |
| `movements:create` | 入库 / 出库 / 盘点，事务内完成 |
| `movements:list` | 按时间 / 类型 / 来源筛选 |
| `attachments:upload` / `delete` / `openExternal` | 附件，上传走系统文件选择框 |
| `locations:tree` / `create` / `update` | 位置维护 |
| `io:pickFile` / `io:previewImport` / `io:commitImport` | 导入三步 |
| `io:export` | 导出，弹系统保存对话框 |
| `barcode:png` / `barcode:print` | 二维码单张 / 批量标签 |
| `app:settings` / `app:backup` / `app:openDataDir` | 设置、手动备份、打开数据目录 |

错误统一 `{ code, message, details }`，`code` 为稳定枚举，前端映射中文文案。绝不把堆栈透给界面。

## 五、MCP 协议设计

### 5.1 传输

| 模式 | 入口 | 适用 |
|---|---|---|
| HTTP（主程序内置） | `http://127.0.0.1:8788/mcp` | WorkBuddy、豆包工作版等支持远程 MCP 的客户端 |
| stdio（转发） | `mcp-bridge.exe` | Codex、Claude Code、Cursor 等 spawn 型客户端 |

两者都需在主程序运行时可用。HTTP 模式强制 `Authorization: Bearer <token>`，Token 在「设置 → AI 接入」一键生成与重置；桥梁进程从设置文件读同一 Token。

### 5.2 工具清单（13 个）

**查询类**

| 工具 | 入参 | 返回 |
|---|---|---|
| `search_components` | `query?, manufacturer?, category?, location_code?, low_stock_only?, limit=20 (max 100)` | `[{id, part_number, manufacturer, quantity, safety_stock, location, package}]` |
| `get_component` | `id?` 或 `part_number + manufacturer?` | 详情 + 最近 10 条流水 |
| `list_low_stock` | `limit=20` | 按缺口降序 |
| `list_suppliers` | `query?, limit=20` | 精简列表 |
| `get_inventory_stats` | — | SKU 数、总库存、预警数、今日笔数 |
| `list_movements` | `component_id?, type?, since?, limit=50` | 流水 |

**写入类**

| 工具 | 说明 |
|---|---|
| `create_component` | 按型号+厂商去重，已存在则返回已有 id |
| `update_component` | 只允许改元信息，**不允许直接改 quantity**（必须走库存工具，保证流水完整） |
| `stock_in` | 入库，事务内写流水 |
| `stock_out` | 出库，库存不足时报错并返回可用量 |
| `adjust_stock` | 盘点校正，写 `adjust` 流水 |
| `create_supplier` / `update_supplier` | |
| `bulk_upsert_components` | `rows[], dry_run?`，返回 `{created, updated, skipped, errors[]}` |
| `export_data` | 导出到 `exports/`，返回绝对路径 |

**刻意不提供 `delete_component` / `delete_supplier`**：AI 误删不可逆，只给 `archive_*`（软归档，界面可恢复）。

### 5.3 健壮性约束

1. **幂等**：写工具接受 `idempotency_key`，命中 `mcp_operation_log` 直接返回上次结果，杜绝 AI 重试导致重复入库。
2. **原子**：`stock_in/out/adjust` 单事务内完成「校验 → 写流水 → 回写库存」。
3. **可追溯**：`operator` 记 `mcp:workbuddy` 等来源，界面可筛。
4. **防打爆**：列表工具 `limit` 硬上限 100，批量工具单次上限 500 行。
5. **错误规范**：`isError: true` + 中文可读信息 + 机器可读 `code`，AI 能据此解释而非抛原始异常。
6. **复用业务层**：工具直接调 `packages/core` 的 service，**不重写业务逻辑、不直接拼 SQL**。界面与 AI 走同一套校验和事务。

## 六、导入导出

**导入三步，防脏数据**：① 系统文件对话框选 `.csv`/`.xlsx`，`chardet` 自动识别编码（GBK 表格不乱码）；② 自动猜测列映射 + 逐行校验，生成报告「新增 120 / 更新 35 / 错误 3（第 47 行型号为空）」，此步**不写库**；③ 确认后在单事务内 upsert，写 `import_batches` 记录，可整批回滚。

**导出**：CSV（UTF-8 **带 BOM**，Excel 双击不乱码）/ XLSX，支持按当前筛选导出，10 万行流式写出不爆内存。

**模板**：内置 `元器件导入模板.xlsx`，含字段说明、示例行与下拉枚举。

## 八、数据安全与长期存储

1. **数据目录**：默认 `%APPDATA%\InventoryManager\`，设置里可改到 `D:\库存数据\` 等位置（支持放到 OneDrive / 坚果云同步目录）。改目录时自动迁移并校验。
2. **热备**：启动时 + 每 24h 用 SQLite `backup()` API 生成一致性快照到 `backups\`，保留 30 份，不阻塞读写。备份前跑 `PRAGMA integrity_check`。
3. **迁移**：Drizzle 迁移随版本内置，启动比对 `__drizzle_migrations` 顺序执行，失败自动回滚；迁移前强制先备份。
4. **安全边界**：所有服务只监听 `127.0.0.1`；MCP HTTP 强制 Token；`nodeIntegration: false` + `contextIsolation: true` + `sandbox: true`；禁用 `will-navigate` 与新建窗口；附件路径做归一化校验防目录穿越；密钥不落日志。
5. **单实例锁**：防止两个进程同时写库。
